# 00 · 代码结构与拆分

> 本文回答三件事：**设计文档里的每个概念落在哪个文件**、**为什么这样拆**、**改动时该动哪里**。
> 上层设计见 [README](README.md) 与 [01 架构总览](01-架构总览.md)；本文只讲落地形态。

## 1. 顶层布局

```
.
├── orchestrator/                     # 子项目 1：编排层（自包含，可单独发版）
│   ├── pyproject.toml  MANIFEST.in  README.md
│   ├── src/iqe_orchestrator/
│   └── tests/
├── agents/                           # 子项目 2：8 个 Agent（自包含，可单独发版）
│   ├── pyproject.toml  MANIFEST.in  README.md
│   ├── src/iqe_agents/
│   └── tests/
├── tests/                            # 跨子项目测试：unit / contract / integration
├── docs/                             # 架构文档 + 运行手册
├── deploy/                           # k8s 清单 + 部署脚本
├── scripts/                          # run_local / sync_common / check_secrets
├── pyproject.toml                    # 工作区根：lint/format/test 配置 + dev 依赖（packages = []）
├── Makefile  Dockerfile  README.md
```

两个子项目各自是标准 src 布局的 Python 项目，`pip install ./orchestrator` 与
`pip install ./agents` 互不依赖。根 `pyproject.toml` **不打包任何东西**
（`[tool.setuptools] packages = []`），只承担工作区职责：统一 ruff/black/isort/mypy/pytest
配置、dev 依赖、pytest 的 `pythonpath` 与 markers。

## 2. 依赖方向

```text
                    ┌───────────────────────────────┐
                    │  iqe_orchestrator             │
  编译期依赖        │   ├── common/（共享层·真源）   │
  （单向，无环）    │   ├── plan.py  graph.py        │
                    │   └── app.py  dispatch.py ...  │
                    └──────────────┬────────────────┘
                                   │ 仅运行时：RabbitMQ 消息 + Postgres 契约表
                    ┌──────────────┴────────────────┐
                    │  iqe_agents                   │
                    │   ├── common/（共享层·副本）   │
                    │   ├── runtime.py              │
                    │   └── {8 个 Agent}/            │
                    └───────────────────────────────┘
```

**两个子项目之间没有 import 依赖**，只共享两样运行期契约：

1. **总线契约**：subject、信封字段、result 三态（见 [02](02-消息总线与消息契约.md)）。
2. **schema 契约**：`common/data/schemas/{envelope.schema.json, stage-contracts.json, plan.schema.json}`。

契约文件在两边各存一份（字节一致），改契约必须两边同时生效 —— 这就是共享层的存在理由。

## 3. 拆分规则（为什么这么切）

| 代码 | 落点 | 判据 |
|---|---|---|
| LangGraph 图、计划解析/校验/封存、Dispatch-Await、扫描与调度、HTTP API、Web UI、DDL 迁移 | `orchestrator/` | 只有编排层进程需要；单实例、单活 |
| 8 个 Agent 的消费循环、13 个 mode 的剧本、契约校验、幂等记账 | `agents/` | 每个 Agent 独立部署、可横向扩副本 |
| 总线客户端、DB 连接、信封/幂等键、配置、路径、健康探针、结构化日志、Mock 行为注入、指纹与日志蒸馏 | 两边各一份 `common/` | 两个交付单元都要，且都不能反向依赖对方 |

**被否决的第三种做法**：抽一个 `libs/` 公共包让两边依赖它。那样任一子项目单独打镜像时都得
带上第三个包和它的版本约束，"两个子项目完全独立"就不成立，且公共包的版本一旦漂移，
线上会出现"编排层与 Agent 对同一契约理解不同"的故障。代价是共享层要同步，用第 4 节的机械手段兜住。

## 4. 共享层：真源 + 副本 + 门禁

| 角色 | 路径 |
|---|---|
| 真源（只改这里） | `orchestrator/src/iqe_orchestrator/common/` |
| 副本（勿手改） | `agents/src/iqe_agents/common/`（含 `data/`、`tools/`） |
| 同源 DDL | `orchestrator/src/iqe_orchestrator/migrations/001_init.sql` → `agents/src/iqe_agents/migrations/` |
| 同步 | `make sync-common` → `scripts/sync_common.sh`（`rsync -a --delete --exclude __pycache__`；无 rsync 时 tar 兜底） |
| 门禁 | `tests/contract/test_common_parity.py`：按相对路径 + sha256 全量比对，`pytest -m contract` 必跑 |

共享层内部**只允许相对导入**（`from . import paths`），包名差异（`iqe_orchestrator.common` vs
`iqe_agents.common`）由 Python 包机制吸收 —— 这也是两份副本能字节一致的前提。

同步后必须跑：

```bash
make sync-common && make test      # contract 会逐文件比对，不一致直接失败
```

包名**不再叫 `ci_triage`**：`ci_triage` 现在只是 Postgres 数据库名（`PG_DSN` 里的库名），
代码里出现它只可能是在引用库名，不是 import。

## 7. 测试分层与门禁

| 层 | 位置 | 是否需要中间件 | 覆盖 |
|---|---|---|---|
| unit | `tests/unit/`、`orchestrator/tests/`、`agents/tests/` | 否 | 信封/幂等键、计划校验、registry 匹配、stage 契约 |
| contract | `tests/contract/` | 否 | 两份共享层字节一致 + 关键资源存在 |
| integration | `tests/integration/` | 是（MQ+DB+9 进程） | Monitor 场景端到端、Plan 轨迹、日报 |

```bash
make lint format typecheck     # ruff / isort+black / mypy（两个子项目）
make test                      # unit + contract，秒级，commit 前必跑
make selfcheck                  # 剧本与夹具，完全离线
PG_DSN=... make smoke ui-check   # 状态机 / UI 渲染（只要 Postgres 存 checkpoint）
make test-integration          # 需要跑起来的栈
```

## 8. 改动清单（按场景）

**改共享层** → 改 `orchestrator/.../common/` → `make sync-common` → `make test`。
**改总线/schema 契约** → 改 `common/data/schemas/` 与 `common/bus.py` → 同步 → 跑
`ci-selfcheck`（Agent 侧契约）+ `make smoke`（编排侧）。
**加一个 Agent** → `agents/src/iqe_agents/<new>/{__init__,main,playbook}.py` + `common/bus.py`
的 `AGENT_QUEUES` + `stage-contracts.json` + plan schema 的 stage 白名单 + 迁移表 + console script。
**改计划结构** → 先改 `common/data/schemas/plan.schema.json`，再改 `plan.py` 的 V1–V9，
最后补 `orchestrator/tests/test_plan.py` 的正反例。
